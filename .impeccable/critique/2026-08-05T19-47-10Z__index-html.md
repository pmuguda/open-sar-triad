## Design Specificity Verdict

**Domain-smart in the model, domain-blind in the interaction.**

The `FAMILIES` abstraction is genuine SAR authorship — `resolveFamily()` mapping Detected to `GEO → GRD → GEC → SIDD` per provider, `metadataUrl()` knowing ICEYE ships `.xml` for NITF and Umbra publishes one STAC item per acquisition, `claimDir()` handling Umbra's duplicate-basename republishing. None of that lifts into another product.

But every control the user touches is generic. Rows show `provider · date · mode` — the same triple any catalogue shows. Nothing in the download workflow surfaces incidence angle, look direction, orbit pass, polarisation or product size: the actual axes on which an analyst chooses among 215 repeat passes over the same volcano. Swap the strings and it is a shopping cart.

**Deterministic scan:** CLI detector exit 0 on `index.html`, `js/app.js` and the whole tree — 1 advisory finding (`em-dash-overuse`), which is a **false positive**: 10 of the 11 em-dashes are `—` empty-state placeholders in data slots, the 11th is the `<title>` separator. Zero em-dashes in body copy.

In-page detector: 59 findings at 1440×900, 58 at 390×844 — 40 `undersized-ui-text`, 8 `gpt-thin-border-wide-shadow` (all one `--shadow` token, not 8 decisions), 5 `cramped-padding`, 3 `dark-glow`, 2 `text-occlusion`, 1 `overused-font`. Excluded as false positives: `marquee` and `theater-slop-phrase` (both from the detector's own source injected into the DOM), 6 `text-occlusion` on the detector's own overlay badges, and 7 `undersized-ui-text` on Leaflet's stock attribution.

**Visual overlays: not available.** Injection failed against the page as shipped — the `<meta>` CSP at `index.html:15` refuses both inline and cross-port scripts. That is the security posture working as designed. Evidence was gathered from a CSP-stripped copy instead, so no overlay is visible in a browser tab.

## Overall Impression

The thinking behind this workflow is better than the workflow. The product-family model solves a real domain problem elegantly, and then the surface that exposes it undermines it at three separate points — two of which lose the user's data silently.

The single biggest opportunity is not visual: it is that the default state of the download list currently tells every user their list is undownloadable.

## What's Working

**The family abstraction teaches while it operates.** The chip states intent ("Detected imagery · 215"); the row badge then reveals the concrete product per scene — GEC for Umbra, GEO for Capella. Users learn that ICEYE's GRD and Umbra's GEC are the same request by watching it happen, not by reading docs.

**One function feeds both the estimate and the artifact.** `collectDownloadJobs()` is shared by `#dl-count` and the script generator, so the hint and the shipped file cannot structurally disagree. Its inputs are wrong in the pin case; the architecture is right.

**`softDisable()` explains itself.** Clicking a soft-disabled control fires a toast saying why instead of doing nothing. Focusable, still announced, still informative — rare and correct.

## Priority Issues

### [P0] One pinned format silently drops every other scene
`js/app.js:795` — `const primary = usingPrimaryAsset() && !sceneFormat.size;`. A single per-scene pin disables the primary-asset fallback **globally**; every unpinned scene resolves to `[]` and is counted as skipped. Measured: 13 picked, pin one to CPHD, script contains 1 file while `#sel-note` still claims all 13 are used. The header explains it with a falsehood ("none of the selected formats available" when no format is selected).
**Fix:** `primary` should be `usingPrimaryAsset()` alone; unpinned scenes fall back to `_dlUrl`. A per-scene refinement must never change global behaviour. → `/impeccable harden`

### [P0] Every badge reads `—` in the default state
With PRIMARY active `sceneFormats()` returns `[]`, so all rows render `.sel-fmt.is-empty` titled "This scene publishes none of the selected formats" — directly above a line saying 8,878 scenes have download links. This is the state every user lands in.
**Fix:** in PRIMARY mode show the resolved primary format. `—` should mean only "no asset exists". → `/impeccable clarify`

### [P1] The format popover deletes the row it belongs to
`.sel-fmt-pop { grid-column: 1 / -1 }` is inert inside `.recent-row { display: flex }`, so the popover becomes a flex sibling and squeezes `.sel-open` to zero width. The control demanding certainty about *which* scene removes that scene's identity, in a list of UUIDs.
**Fix:** `flex-wrap: wrap` on the row + `flex-basis: 100%` on the popover; echo the scene ID into its header. → `/impeccable layout`

### [P1] Isolate mode contradicts its own readouts and leaves stale state
215 isolated: Coverage says 8,878 and the map footer says "IN VIEW 8,878 SCENES VISIBLE". Empty the list while isolated and `#selIsolate` holds `aria-pressed="true"` and `.is-off` simultaneously while the hint banner still reads "Showing only your download list (13 scenes)" over an empty list — `setSceneSelected` short-circuits to `render()` and never calls `hideHint()`.
**Fix:** call `setIsolateSelection(false)` when the list empties; swap the footer to "IN LIST" while isolating. → `/impeccable harden`

### [P2] 73.7% of visible text renders in Arial
`--mono` is referenced 5 times in `css/style.css` and **never defined**. Those declarations become `unset`, and where the parent is a `<button>` the UA default wins. Character-weighted: Arial 73.7%, IBM Plex Mono 25.3%. The whole Recent tray is Arial. Both assessments found this independently — A by reading, B by measuring the computed font chain with all 10 IBM Plex faces confirmed loaded.
**Fix:** one-word change, `var(--mono)` → `var(--font-mono)`. → `/impeccable typeset`

## Persona Red Flags

**Alex (power user).** `+` gives him 8,878 scenes; the tray renders 200 with "+8,678 more (not shown)" — 98% of his basket unauditable, with no sort, search or group-by-provider. Tab order runs dock → help → AOI toolbar; there is no keyboard route from the dock into the tray. `#dl-exact-toggle` silently discards his family selection and re-exposes the exact trap the family layer exists to hide (`SLC · 0` beside `SICD · 13`). Then the pin trap costs him the download.

**Sam (accessibility, beyond the measured pass).** `#sel-note` and `#dl-count` are not live regions, so the two numbers defining what will be downloaded change silently. `#hint-banner` is a bare `<div>` with no role, so the isolate explanation is never announced — and its stale-state bug is invisible to him. `#selIsolate` reports `aria-pressed="true"` and `aria-disabled="true"` at once. In the paper theme the picked-row tint sits in nearly the same hue family as the Capella provider swatch, so on a Capella stack "selected" and "Capella" are the same colour.

**Riley (stress tester).** 215 isolated footprints render as one opaque mass — `fillOpacity: 0.45` saturates after ~5 overlaps, so the dashed selection outline is invisible in exactly the stack that needed it. Hovering a row whose footprint is off-viewport highlights nothing and says nothing. At 390×844 the hint banner and AOI toolbar overprint each other and the Leaflet attribution.

## Minor Observations

- The amber rule is broken in the picker: `.picker-check` renders the unpicked `＋` in the same amber as the picked `✓`; `.picker-bulk` and all three Export button icons are amber while nothing is selected.
- `.picker-row.is-picked` is declared after `.picker-row:hover` at equal specificity, so picked rows have **no hover response at all**.
- 40 `undersized-ui-text` findings; at 390px the timeline ticks and coordinate labels drop to 7.5px.
- `#sel-note` bleeds to the viewport edge at 390 (`body-text-viewport-edge`).
- `scenes.geojson` is 27.24 MiB served uncompressed — 99.24% of page weight. gzip gives 10.7× (2.55 MB). Nav-to-ready is ~900ms on loopback and would be dominated by this on any real network.
- `frame-ancestors` in the `<meta>` CSP is inert; it requires an HTTP header. The rest of the CSP works — it blocked the design tool's own injection.
- Toast vocabulary splits: "215 scenes selected" vs "8,878 scenes in the download list".
- Pluralisation: "download.sh ready · 1 files", "1 of 13 scene publishes CPHD".
- `.sel-fmt-clear` renders a clickable "FOLLOWING THE LIST DEFAULT" that does nothing when no pin exists.
- `#dl-exact-toggle` is styled identically to the static label above it — 9px, uppercase, `--ink-3`, no border, zero affordance that it is a button.
- Four different `✕` scopes: remove row, clear list, clear AOI, close preview.

## Questions to Consider

1. If the family abstraction is the right mental model, why does every downstream surface — the row badge, the popover, the script's folder names, the export hint — revert to raw acronyms? Who is the family layer for, and does it survive first contact with what it names?
2. An empty download list means "download all 8,878"; a one-item list means "download 1". That switch has no control, no label, and an 8,878× blast radius. What if scope were explicit — *Everything filtered* vs *Only my picks*?
3. Isolate mode resolves 215 stacked footprints into one blob. If a map physically cannot show what is in the basket at SAR's real density, is the map the right place to verify a basket?
4. The generated `download.sh` header is the only artifact that tells the truth about what is about to happen. Why is that summary written to a file opened *after* committing, instead of shown *before*?
